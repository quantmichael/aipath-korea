# PHASE 12J — Evidence integration contract

This worktree starts at the PHASE 12E release commit `560aaf1` and carries forward the uncommitted PHASE 12G search-only safety, 12H quality, and 12I official-evidence work in a separate checkout. It does not contain Opportunity Status Automation or Vercel Preview changes from the unrelated `main` checkout.

## Existing database path

| Stage | Existing identity and link |
| --- | --- |
| Discovery Query | `agent_discovery_queries.id` PK |
| Search Result | `agent_search_results.id` PK; `query_id` FK to Query |
| Source Candidate | `agent_source_candidates.id` PK; unique `search_result_id`, composite `(search_result_id, query_id)` FK; nullable `promoted_source_id` FK to Source |
| Approved Source | `agent_sources.id` PK; `provenance.search_result_id` and `provenance.source_candidate_id` cross-check the promotion; `source_review.approval` binds active status and collection permission |
| Collection | `agent_collection_runs.id` PK, `source_id` FK; `agent_raw_documents.id` PK, `(run_id, source_id)` FK to run, `source_id` FK to Source |
| Processing | `agent_processing_jobs.id` PK, `raw_document_id` FK, unique `(raw_document_id, processing_version)`, `candidate_id` and `verification_id` FKs |
| Candidate | `agent_candidates.id` PK, `(raw_document_id, run_id, source_id)` FK to RawDocument |
| Verification | `agent_verifications.id` PK, `candidate_id` FK; `(id, candidate_id)` unique pairing |
| Publish Queue | `agent_publish_queue.id` PK, unique `candidate_id` FK and `(verification_id, candidate_id)` FK to Verification |

`SupabaseEvidenceIntegration.assess` follows these keys with exact IDs and read-only SDK queries. It does not infer a Source from a matching domain or choose an arbitrary latest RawDocument. Search-only results without a promoted Source remain unverified. It checks the trusted access snapshot before a private Storage download, then delegates raw SHA-256, URL relation, and field replay to the PHASE 12I assessor. A prior `REVIEW_REQUIRED` Candidate, mismatched saved Gate decision, absent queue, or unresolved evidence cannot contribute to publish-ready conversion. The adapter never inserts, updates, deletes, searches Tavily, calls OpenAI, or publishes Service data.

The existing `QualityGateRunner` now leaves a reviewed extraction, unnormalized or date-only application time, missing exact recruitment start/deadline, or expired exact deadline in `REVIEW_REQUIRED`. It still uses the existing Verification and Publish Gate before a `PUBLISH_READY` decision and queue insert. This is a safety change to the *Agent* processing path; it is not deployed by this work.

## Metrics and cohorts

`integration_metrics(rows, cohort=...)` requires one explicit `synthetic` or `operational` cohort and rejects mixed rows. Evidence Resolution Rate = resolved official results / all official results; Verified Opportunity Yield = verified new opportunities / all search results; Publish-ready Conversion Rate = publish-ready results / verified new opportunities. Empty denominators return zero. `review_required_count` includes an Evidence hold, saved Gate review, or integration link/access problem, so it can overlap duplicate count. A queue is counted as publish-ready only if verified original evidence, a terminal successful Processing Job, VERIFIED Verification, matching saved Gate decision, and matching READY queue all agree.

Unchanged raw SHA-256 may create another RawDocument metadata row for audit. The existing cross-raw cache replays compatible evidence onto a **new provenance-bound Candidate** for that new RawDocument, without another LLM call; a repeat of the same raw/version job is idempotent. These are intentional records, not proof of a new opportunity. The verified-opportunity dedup and metrics exclude the repeat from new yield.

## Root cause and scope

PHASE 5 ICCAI 후보 `8affb3c0-db03-44a0-9d0e-5a246f2dbadc` had 0/20 validated fields. The page was **not** truncated: the earlier preprocessor produced 4,603 characters under the 12,000-character limit. The source included the conference name, Yonsei University, Seoul, registration deadline, event range, and registration link. However, date labels and year/day fragments were split over separate lines (`Registration Deadline:` / `Dec. 20,` / `2026`; `Conference Dates: Apr.` / `23-26, 2027`). We do not claim a more specific cause than the retained data supports.

PHASE 5.5 retains the existing provider port, strict structured output, budget defaults (5/day, 100/month), Agent-only persistence, and model `gpt-5.4-nano`. It changes only how evidence is cited and deterministically verified. No migration or Service DB change was needed.

## Evidence blocks and links

The deterministic HTML preprocessor removes script/style/navigation/cookie/footer noise, then assigns ordered IDs `B001…` to meaningful text units. Each selected block records `block_id`, text, original line position, and SHA-256 content hash. Short adjacent date fragments are joined before IDs are assigned. Link IDs `L000…` record anchor text, safe absolute `href`, and source position; `L000` explicitly represents the fetched page URL. IDs are reproduced from the same content and preprocessor version. Input selection prioritizes initial identity and conference/registration/deadline/date/schedule/venue/location/organizer/fee/price signals instead of blindly keeping the prefix. The actual ICCAI page yielded 102 selected blocks, 9 selected links, 6,087 input characters, and no truncation. Key blocks were `B012` (host), `B038` (registration deadline), and `B039` (conference date range).

The model receives numbered blocks and links, not unlabelled page prose. Its strict schema returns `value`, `evidence_block_ids`, `link_ids`, `confidence` per field, plus conference and document-confidence flags. Prompt version is `conference-grounded-2026-10-04-v2`; schema/extraction version is `conference-grounded-v2`. The prior `conference-v1` candidate remains unchanged; the new fingerprint includes both versions so the same RawDocument can be extracted once under the new policy.

## Resolution and validation

Application code resolves IDs only from blocks/links actually sent to the model. Missing or unknown block IDs invalidate a text field. For text fields, Unicode NFKC, whitespace, punctuation, and case are normalized before conservative substring comparison. This is not semantic fuzzy matching. Multiple blocks can jointly support a value; no more than five block IDs are accepted per text field. Date fields additionally require a full, unambiguous year-bearing date whose parsed value occurs in the cited block text; a range such as `Apr. 23-26, 2027` supports April 23 and 26, not an unrelated day or year. Relative and yearless dates remain null.

URL fields resolve exactly one selected link ID, validate the resolved href through the existing URL safety utility, and reject a conflicting model-authored URL. A fetched-page `L000` ID can support the official URL. Resolved `evidence_text` is generated by code from source blocks or links, capped at 240 characters for storage. Model-written evidence prose is not trusted. Missing/invalid evidence or a value mismatch yields null, confidence 0, a validation status, and a review reason. New code discards extraneous block IDs on successfully link-resolved URL fields.

## Remaining limits and model decision

The nine grounded fields are a material improvement, so automatic model escalation is not warranted by this single page. More public Conference pages and different HTML layouts are required before production quality is established. The present local RawDocument store is not a durable operational volume, and concurrent workers do not receive an atomic LLM budget reservation. No PHASE 6 implementation was started.

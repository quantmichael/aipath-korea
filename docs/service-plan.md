# AI PATH KOREA 서비스 기획서

## 서비스 목적

AI와 여러 산업이 결합되는 환경에서 사용자가 자신에게 필요한 학습·도전·네트워킹 기회를 발견하도록 돕습니다.

## 핵심 사용자

AI를 학습하거나 업무·진로에 접목하려는 입문자와 성장 단계의 사용자입니다.

## 초기 기회 유형

- 교육
- 공모전
- 해커톤
- 밋업
- 콘퍼런스
- 웨비나
- 성장 프로그램

## 핵심 사용자 흐름

사용자는 검색·필터 또는 DB 기반 AI 추천으로 기회를 찾고, 상세 정보와 출처를 확인한 뒤 공식 페이지로 이동합니다.

## 페이지 구성

- 홈: 서비스 소개, 주요 기회 유형, 탐색/추천 진입 버튼
- 기회 탐색: 키워드 검색, 카테고리/상태/참여 방식/참가비 필터
- 기회 상세: 일정, 장소, 참가 대상, 참가비, 출처, 공식 페이지 링크
- AI 추천: 사용자 조건 입력 폼과 추천 결과
- 서비스 소개: 서비스 목적, 데이터 원칙, AI 추천 기준

## 핵심 기능

- Supabase DB에 등록된 AI 기회 목록 조회
- 기회별 상세 정보 조회
- 프론트엔드 검색/필터링
- OpenAI API를 활용한 DB 기반 맞춤 추천
- API 오류, 추천 후보 없음, 연결 실패 상황 안내

## 데이터 운영 원칙

- 관리자 큐레이션과 이용 가능한 공식 API를 혼합합니다.
- MVP는 검증된 정보 약 20~30개로 시작합니다.
- 모집 마감일과 실제 행사 개최일을 별도로 관리합니다.
- 출처, 이용조건, 마지막 확인 시각을 기록합니다.
- 일정 변경 가능성을 알리고 최종 확인은 공식 원문에서 하도록 안내합니다.

## AI 기능 기준

- 입력: 수준, 관심 분야, 목적, 참여 방식, 비용, 가능한 기간
- 출력: 최대 3개의 실제 기회와 추천 이유
- 실패 처리: 필수값 누락, 추천 후보 없음, API 오류, 서버 연결 실패 또는 지연
- 제한: DB에 없는 기회를 생성하거나 지원 자격·선정 가능성을 보장하지 않음

## AI 응답 지연 개선 기준

- 사용자가 추천을 요청하면 즉시 로딩 상태를 보여주고 버튼을 비활성화합니다.
- 추천 후보는 최대 30개로 제한해 AI API에 전달하는 데이터 양을 줄입니다.
- AI에는 후보 전체 데이터가 아니라 추천 판단에 필요한 제목, 요약, 일정, 카테고리, 태그 중심 데이터를 전달합니다.
- 동일 조건 요청이 반복되는 경우 서버 또는 외부 캐시에 일정 시간 저장하는 전략을 적용할 수 있습니다.
- AI API가 지연되거나 실패하면 가벼운 모델 또는 규칙 기반 추천으로 대체할 수 있습니다.
- 후보 데이터가 많아지면 요약/페이징을 적용해 API 요청 크기를 줄입니다.

## 기술 구성

- 프론트엔드: HTML, CSS, Vanilla JavaScript
- 백엔드: Python FastAPI 기반 Vercel Serverless Functions
- 데이터베이스: Supabase PostgreSQL
- AI API: OpenAI Responses API
- 배포: GitHub, Vercel
